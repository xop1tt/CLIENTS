# Безопасность и конфиденциальность

Сообщить об уязвимости: **Security → Report a vulnerability** в репозитории, не публичным issue.
Подробнее: [SECURITY.md](https://github.com/xop1tt/CLIENTS/blob/main/SECURITY.md).

## Приложение для macOS

- Приложение обращается только к самим источникам (FL.ru и ваши RSS-ленты, t.me, api.vk.com, overpass-api.de),
  к сайтам найденных организаций (один запрос на главную страницу) и раз в сутки к публичному API GitHub для проверки
  обновлений (отключается).
- Никаких своих серверов и аналитики: у локальной учётной записи лиды не покидают Mac.
- Облачная учётная запись дополнительно хранит данные в **вашем** проекте Supabase. Доступ к строкам — только у владельца
  (Row Level Security). В приложении хранятся только адрес проекта и публичный ключ; с секретным ключом приложение
  работать откажется.
- Ключ VK, запомненный вход и токены облака лежат в Связке ключей. Пароли локальных учётных записей — только в виде
  соли и хэша PBKDF2-SHA256 (310 000 итераций).
- Отчёты о сбоях сами никуда не уходят: вы видите и правите текст, домашняя папка и имя пользователя скрыты.
- Обновления: dmg сверяется по SHA-256 из того же релиза. Это защита от повреждённой загрузки, а не подпись Apple:
  сборка подписана ad-hoc.

## Python-версия в GitHub Actions

- Секреты хранятся только в GitHub Secrets и вычищаются из логов, из текста ошибок и из уведомлений.
- Логи Actions в публичном репозитории видны всем. Поэтому в них пишутся только счётчики и названия источников, без
  текстов заявок и контактов (для локальной отладки есть `LEADGEN_SHOW_MESSAGES=1`).
- Кэш состояния шифруется (Fernet). Кэш публичного репозитория могут прочитать workflow из PR форков, поэтому без ключа
  данные бесполезны. Без `STATE_ENCRYPTION_KEY` состояние в кэш не сохраняется вообще.
- SQL-запросы только параметризованные. URL сайтов проверяются: только http(s), без локальных адресов.

## Репозиторий и CI

- Ветка `main` защищена: слияние только через PR после зелёных проверок.
- CodeQL, dependency review, Dependabot, secret scanning и push protection.
- Права workflow минимальные (`contents: read`, запись только у выпуска релиза). Сторонние Actions закреплены по полным
  SHA, Dependabot предлагает обновления.
- `tests.yml` не получает секретов, `pull_request_target` не используется. Ввод `workflow_dispatch` передаётся в shell
  через переменные окружения и проверяется регуляркой.

## Правила сбора данных

- CAPTCHA, авторизация и запреты `robots.txt` не обходятся. Источники с запретами не подключены.
- Сохраняются только контакты, которые человек или организация сами опубликовали. Используйте их в рамках 152-ФЗ
  и правил площадок.
- Для холодных рассылок по найденным контактам законодательство РФ требует осторожности: это решение владельца,
  а не системы. Приложение не делает массовых рассылок: черновик обращения отправляется только вручную.
