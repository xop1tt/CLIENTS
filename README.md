# Lead Generator

Автономная бесплатная платформа поиска потенциальных заказчиков на разработку: сайты, Telegram-боты,
приложения, автоматизация, CRM, доработки. Работает по расписанию в GitHub Actions, оценивает находки
собственными правилами (без AI API), хранит в Notion и присылает уведомления в Telegram.

> **Публичным должен быть код, а не собранная база.** Лиды и контакты хранятся в Notion и в
> зашифрованном кэше GitHub. В репозиторий и в логи Actions они не попадают.

## Как это работает

```
GitHub Actions (cron, раз в час)
  │  восстановить зашифрованное состояние из кэша → нет кэша? восстановить ключи из Notion
  ▼
Источники (каждый со своим интервалом, лимитами, курсором и журналом ошибок)
  FL.ru RSS · Telegram-каналы · VK-сообщества · OpenStreetMap + проверка сайтов
  ▼
Нормализация → Lead (единая модель) → собственный scoring → дедупликация (ID + отпечаток текста/домена)
  ▼
Маршрутизация во внешние адаптеры (необязательно): webhook (Make/n8n), Hunter
  ▼
Notion (upsert, с повторными попытками; недоступен → ждёт в локальной базе)
  ▼
Telegram (лиды, дайджест, ошибки одним сообщением, восстановление, сводка раз в сутки)
  ▼
зашифровать состояние → сохранить в кэш
```

Структура кода:

```
src/leadgen/
  core/          модель Lead, HTTP-клиент (лимиты, ретраи, бюджет запросов), логирование без секретов
  config/        загрузка config.yaml и секретов из окружения
  sources/       rss, telegram_web, vk, osm_overpass, site_checker, registry
  scoring/       правила, веса, пороги, разбор бюджета
  integrations/  базовый адаптер + Router, webhook, hunter
  storage/       SQLite, Notion, шифрование состояния, экспорт
  notifications/ Telegram и фразы
  scheduler/     конвейер запуска, интервалы, диагностика
  cli.py         python -m leadgen run|diagnose|state|export|notion-init
tests/           70 тестов на фикстурах, сеть заблокирована
.github/workflows/  search.yml (расписание), tests.yml, diagnose.yml
```

Если отключить Notion, Telegram и все адаптеры, поиск, оценка и дедупликация продолжают работать.
Результаты остаются в зашифрованном состоянии и уходят в Notion, когда он снова доступен.

## Источники: что реально работает

| Источник | Статус | Что собирает | Ограничения |
|---|---|---|---|
| **FL.ru** (`fl_ru`) | ✅ включён | Название, описание, бюджет (если в тексте), дата, ссылка, контакты из текста | RSS хранит только последние записи: если система стоит больше суток, часть заказов будет пропущена. Система предупреждает об этом |
| **Telegram-каналы** (`telegram_channels`) | ✅ включён, список каналов пуст | Текст поста, дата, ссылка на оригинал, @username/телефон/email из текста | Только публичные каналы с веб-превью `t.me/s/…`. Приватные каналы и чаты нельзя читать без пользовательского аккаунта (MTProto), это вне правил ТЗ. После пропущенных запусков листает до 3 страниц назад (настраивается) |
| **VK-сообщества** (`vk_communities`) | ⏸ выключен | Посты открытых сообществ | Нужен бесплатный сервисный ключ. Поиска по всему VK нет, читаются только стены выбранных сообществ |
| **OpenStreetMap** (`osm_organizations`) | ✅ включён | Название, категория, адрес, телефон, сайт, ссылка на объект OSM | Полнота данных OSM в РФ ниже, чем у Яндекса и 2ГИС. Факт «сайт не указан» означает, что сайта нет в OSM, а не что его нет совсем |
| Проверка сайтов | ✅ | Доступность, HTTPS, мобильная вёрстка, год в копирайте, признаки онлайн-записи | Проверяется только главная страница, не чаще одного раза в 60 дней |

**Не подключены:** Kwork, Freelance.ru, Habr Freelance, Workspace, Яндекс Услуги, Яндекс Карты, 2ГИС
и поисковые системы. Причина для каждого описана в [docs/research.md](docs/research.md). Если коротко:
у этих площадок нет бесплатного разрешённого способа получать данные, или их условия запрещают хранить
данные, или бесплатный доступ даётся только на пробный период.

> ⚠️ Из среды разработки внешние сайты были недоступны, поэтому все парсеры проверены на тестовых
> данных, построенных по документированным форматам. Первую живую проверку нужно сделать самостоятельно
> (шаг 7 установки).

### Факты и предположения

У каждой организации два отдельных списка:

- `facts`: только то, что проверено. Например, «В OpenStreetMap не указан сайт», «Сайт не открылся
  при проверке 05.11.2026: HTTP 503», «Нет meta viewport».
- `assumptions`: предположения. Например, «Возможно, нужна онлайн-запись».

Оценка («Высокая релевантность», 72/100) всегда подаётся как оценка системы, а не как факт.

## Внешние интеграции

| Сервис | API | Бесплатный постоянный доступ | AI-функции через API | Статус |
|---|---|---|---|---|
| Notion | Да | Да, API доступен на бесплатном тарифе; лимит в среднем 3 запроса/с | Нет | ✅ Основное хранилище |
| Telegram Bot API | Да | Да | Нет | ✅ Уведомления |
| Hunter.io | Да (Domain Search) | Да, бесплатный тариф 50 кредитов/мес (hunter.io/pricing) | Нет, в API только данные о контактах | ✅ Адаптер готов, выключен |
| Make | Да, входящие webhook | Бесплатный тариф есть; размер лимита операций в этой сессии не проверял | Есть AI-модули, но бесплатность в API не подтверждена | ✅ Через универсальный webhook, выключен |
| n8n Community Edition | Да, webhook | Само ПО бесплатное, но нужен свой сервер. Бесплатного постоянного хостинга нет, можно запустить на своём компьютере | Да, если подключить локальную модель (например, Ollama на своём ПК) | ✅ Через универсальный webhook, выключен |
| Snov.io | Да | Бесплатный тариф: 50 кредитов/мес, но **доступ к API на бесплатном тарифе даётся только по запросу через демо** (snov.io/api) | Нет | ❌ Не подключён |
| Apollo.io | Да | Бесплатный тариф с кредитами есть; доступ к API на бесплатном тарифе подтвердить не удалось | AI-задачи Assistant тратят кредиты | ❌ Не подключён |

Ни один сервис не даёт бесплатного постоянного AI-анализа через API, поэтому основная фильтрация
работает на правилах. Самый реальный бесплатный вариант AI: n8n + локальная модель на своём
компьютере, подключённые через webhook. Ограничение: компьютер должен быть включён.

### Как устроены адаптеры

- У каждого адаптера своя секция в `integrations`: `enabled`, `route` (какие лиды отправлять),
  `fields` (какие поля передавать), `max_per_run`, `monthly_quota`.
- Повторно одна заявка в тот же сервис не отправляется.
- Результат хранится отдельно (`external_results`) и не меняет исходные данные.
- Итоговая оценка = 75% своя + 25% средняя внешняя (`scoring.external_weight`).
- После 3 ошибок подряд адаптер пропускается до следующего запуска, остальная система продолжает работу.
- В режиме dry-run во внешние сервисы ничего не отправляется.

**Формат webhook.** POST JSON с полями из `fields`, заголовок `X-Leadgen-Signature` с HMAC-SHA256 тела
(ключ `WEBHOOK_SECRET`). Ответ необязателен; если он есть, ожидается формат
`{"score": 0-100, "label": "строка", "comment": "строка", "details": {...}}`.

## Подтверждённые бесплатные лимиты

Указаны только лимиты, которые подтверждены официальными страницами на 05.11.2026.

| Компонент | Условие |
|---|---|
| GitHub Actions | Стандартные раннеры в публичных репозиториях бесплатны. Кэш до 10 ГБ на репозиторий, записи без обращений 7 дней удаляются. Расписание отключается после 60 дней без активности в репозитории |
| Hunter.io | 50 кредитов в месяц (поиск email = 1, проверка = 0,5). Адаптер по умолчанию тратит не больше 25 |
| Snov.io | 50 кредитов в месяц, API на бесплатном тарифе только по запросу |
| 2ГИС | Демо-ключ: один раз, на 1 месяц, поэтому не используется |
| Яндекс Карты | Бесплатно только без сохранения данных, поэтому не используется |
| Overpass API | Публичный сервер, правила честного использования. Система делает 1 запрос на пару «регион × категория» не чаще раза в неделю |

## Установка шаг за шагом

### 1. Опубликовать репозиторий

1. На github.com нажмите **New repository**, задайте имя `lead-generator` и видимость **Public**
   (Actions в публичных репозиториях бесплатны). README не добавляйте.
2. Загрузите код:
   ```bash
   cd lead-generator
   git init && git add . && git commit -m "Lead Generator MVP"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/lead-generator.git
   git push -u origin main
   ```
3. Проверьте вкладку **Actions**: workflow **Tests** должен стать зелёным.

### 2. Telegram-бот

1. Напишите [@BotFather](https://t.me/BotFather) команду `/newbot`, задайте имя и сохраните токен.
   Это значение для `TELEGRAM_BOT_TOKEN`.
2. Напишите своему боту любое сообщение.
3. Откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите `"chat":{"id": ...}`.
   Это значение для `TELEGRAM_CHAT_ID`. Для группы добавьте бота в группу, и id будет отрицательным.

### 3. Notion

1. Откройте [notion.so/profile/integrations](https://www.notion.so/profile/integrations), нажмите
   **New integration** (тип Internal) и скопируйте токен в `NOTION_TOKEN`.
2. Создайте пустую страницу, например «Лиды», и через меню **⋯ → Connections** подключите к ней интеграцию.
3. Создайте базу с нужными полями одной командой (локально, нужен Python 3.11+):
   ```bash
   pip install -r requirements.txt
   NOTION_TOKEN=... PYTHONPATH=src python -m leadgen notion-init --parent <ID страницы>
   ```
   ID страницы — 32 символа в конце её адреса. Команда напечатает ID базы, это `NOTION_DATABASE_ID`.

   Без Python поля можно создать вручную. Список полей и их типов — в `SCHEMA` в
   `src/leadgen/storage/notion.py`.

### 4. Ключ шифрования состояния

```bash
python -c "import secrets; print(secrets.token_urlsafe(32))"
```

Сохраните результат в `STATE_ENCRYPTION_KEY`. Если ключ потерять или сменить, система восстановится из
Notion (за последние `storage.restore_days` дней).

### 5. GitHub Secrets и переменные

Откройте **Settings → Secrets and variables → Actions**.

**Secrets** (обязательные): `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, `NOTION_TOKEN`,
`NOTION_DATABASE_ID`, `STATE_ENCRYPTION_KEY`.
**Secrets** (необязательные): `VK_SERVICE_TOKEN`, `HUNTER_API_KEY`, `WEBHOOK_URL`, `WEBHOOK_SECRET`.

**Variables:** `LEADGEN_MODE`. Пока переменная не задана, система работает в режиме `dry-run` и
ничего не отправляет.

### 6. Настроить источники

Скопируйте `config.example.yaml` в `config.yaml`, отредактируйте и закоммитьте. Файл публичный,
поэтому личных данных и секретов в нём быть не должно.

- `telegram_channels.channels`: имена публичных каналов с заказами. Проверьте, что адрес
  `https://t.me/s/<имя>` открывается в браузере.
- `osm_organizations.regions`: ваш город, например `{name: Казань}`.
- Для VK создайте приложение на [dev.vk.com](https://dev.vk.com), возьмите **сервисный ключ доступа**,
  положите его в `VK_SERVICE_TOKEN`, заполните `communities` и поставьте `enabled: true`.

### 7. Первая проверка (без реальных уведомлений)

1. Запустите **Actions → Diagnose → Run workflow**. В выводе будет видно, какие секреты заданы и какие
   источники готовы.
2. Запустите **Actions → Lead search → Run workflow** с `force: true`. Режим по-прежнему dry-run:
   в Summary запуска будет видно, сколько найдено и какие источники упали. Содержимое лидов в публичный
   лог не пишется.
3. Если источник падает (например, FL.ru блокирует зарубежные IP), об этом будет сказано в Summary.

### 8. Боевой режим (только после вашего решения)

1. Задайте переменную `LEADGEN_MODE` = `live`.
2. Запустите **Diagnose** с `ping: true`: в Telegram должно прийти тестовое сообщение, в выводе — `Notion: {'ok': True}`.
3. Дальше всё работает по расписанию.

Уведомления о лидах, найденных в режиме dry-run, при переходе в live повторно не приходят.

## Расписание

Workflow запускается каждый час, а каждый источник сам решает, пора ли ему работать (`interval_hours`):

| Источник | По умолчанию |
|---|---|
| FL.ru | 2 ч |
| Telegram-каналы | 3 ч |
| VK | 3 ч |
| OpenStreetMap | 120 ч (5 дней), один и тот же запрос не чаще 7 дней |

- Расписание GitHub может задерживаться. Интервалы считаются с допуском 10 минут.
- После сбоя источник пробуют снова на следующем часовом запуске.
- Пропущенные запуски: RSS и каналы догоняют с последней обработанной записи в пределах истории
  источника (у RSS это последние записи ленты, у каналов `max_pages_per_channel` страниц).
  Если догнать не удалось, в Summary появится предупреждение.
- Параллельные запуски исключены: `concurrency: lead-search`.
- **60 дней без активности.** GitHub отключает расписание публичного репозитория, если в нём 60 дней
  не было коммитов. На 50-й день бот предупредит в Telegram. Искусственных коммитов система не делает:
  сделайте осмысленный коммит (например, обновите настройки) или после отключения нажмите
  **Enable workflow** во вкладке Actions.

## Настройка фильтров и оценки

Все параметры находятся в `scoring` в `config.yaml`:

- `project_types`: типы проектов и ключевые слова (можно указывать начало слова, например `автоматизац`).
- `intent_keywords`: признаки реального запроса («ищу», «нужен», «требуется»).
- `offer_markers`: признаки того, что исполнитель предлагает услуги, а не ищет его (штраф).
- `stop_words`: сразу «Не подходит» (вакансии в штат, казино и т. п.).
- `spam_markers`, `urgency_keywords`, `business_markers`, `hard_markers`: спам, срочность, тип
  заказчика, сложно выполнимые задачи.
- `weights`: вес каждого критерия. `thresholds`: пороги категорий высокая/средняя/низкая.
- `max_age_days`: заявки старше этого срока отбрасываются.
- `organizations.weights` и `category_weights`: оценка привлекательности организаций.

В Notion в поле «Score Reasons» видно, за что начислены баллы. По этому полю удобно подстраивать веса.

## Добавление источников и сервисов

**Ещё одна RSS-лента** — кода не нужно, достаточно добавить её в `feeds`:

```yaml
  my_feed:
    type: rss
    enabled: true
    interval_hours: 2
    feeds: [{url: https://example.ru/rss}]
```

**Новый тип источника:**

1. Создайте класс в `src/leadgen/sources/`, унаследуйте его от `Source` и реализуйте
   `fetch(since, cursor) -> FetchResult`.
2. Зарегистрируйте класс в `sources/registry.py`.
3. Добавьте блок в конфиг.
4. Напишите тест на фикстуре.

Новый адаптер подключается так же: класс от `Adapter` с методом `process(lead)`, регистрация в
`integrations/registry.py`.

**Будущие команды бота** (`/status`, `/stats`, `/pause`…). Данные для них уже есть в `source_state`,
`request_stats` и `errors`, а `python -m leadgen diagnose` выводит то же самое. Команды можно реализовать
отдельным workflow, который раз в N минут читает `getUpdates`. В первую версию они не вошли.

## Резервное копирование

Основная копия — база Notion (её можно экспортировать средствами Notion). Локальная выгрузка:

```bash
PYTHONPATH=src python -m leadgen export --format json --out backup/leads.json
PYTHONPATH=src python -m leadgen export --format csv  --out backup/leads.csv
```

Папка `backup/` в `.gitignore`. **Не коммитьте выгрузки** в публичный репозиторий.

## Безопасность

- Секреты хранятся только в GitHub Secrets и вычищаются из логов, из текста ошибок и из уведомлений.
- Логи Actions в публичном репозитории видны всем. Поэтому в них пишутся только счётчики и названия
  источников, без текстов заявок и контактов (для локальной отладки есть `LEADGEN_SHOW_MESSAGES=1`).
- Кэш состояния шифруется (Fernet). Кэш публичного репозитория могут прочитать workflow из PR форков,
  поэтому без ключа данные бесполезны. Без `STATE_ENCRYPTION_KEY` состояние в кэш не сохраняется вообще.
- Права workflow: `contents: read`. Сторонние Actions закреплены по полным SHA, Dependabot предлагает
  обновления.
- `tests.yml` не получает секретов, `pull_request_target` не используется. Ввод `workflow_dispatch`
  передаётся в shell через переменные окружения и проверяется регуляркой.
- SQL-запросы только параметризованные. URL сайтов проверяются: только http(s), без локальных адресов.
- CAPTCHA, авторизация и запреты robots.txt не обходятся. Источники с запретами не подключены.
- Персональные данные: сохраняются только контакты, которые человек или организация сами опубликовали.
  Используйте их в рамках 152-ФЗ и правил площадок. Для холодных рассылок по найденным контактам
  законодательство РФ требует осторожности: это решение владельца, а не системы.

## Частые проблемы

| Симптом | Что делать |
|---|---|
| Ничего не приходит в Telegram | Проверьте `LEADGEN_MODE=live` и запустите Diagnose с `ping`. Убедитесь, что вы написали боту хотя бы одно сообщение |
| `Notion: missing_properties` | В базе не хватает полей. Создайте базу через `notion-init` или добавьте поля вручную |
| Notion 401/404 | Интеграция не подключена к странице/базе (**⋯ → Connections**) |
| Источник `fl_ru` падает с 403/таймаутом | Площадка не пускает IP GitHub. Временно выключите источник, обойти это нельзя |
| `telegram_channels: нет публичного превью` | У канала выключено веб-превью или неверное имя |
| `VK API 5` | Неверный сервисный ключ. `VK API 15/30` — сообщество закрытое |
| «Не удалось расшифровать кэш» | Сменился `STATE_ENCRYPTION_KEY`. Состояние восстановится из Notion |
| Расписание перестало работать | Прошло 60 дней без коммитов. Нажмите **Enable workflow** в Actions |
| Много мусора или мало заявок | Подстройте `stop_words`, `weights` и `thresholds`, ориентируясь на «Score Reasons» в Notion |

Локальный запуск:

```bash
pip install -r requirements-dev.txt
python -m pytest                                  # 70 тестов, без сети
PYTHONPATH=src python -m leadgen diagnose
PYTHONPATH=src python -m leadgen run --sources fl_ru --force   # dry-run по умолчанию
```

## Ограничения и что дальше

- Источников готовых заказов, работающих бесплатно и в рамках правил, немного: FL.ru RSS, публичные
  Telegram-каналы и VK. Основной объём, скорее всего, дадут Telegram-каналы, которые вы подберёте.
- OSM заменяет Яндекс Карты и 2ГИС лишь частично: малого бизнеса там меньше.
- Playwright не используется: везде, где он мог бы понадобиться, сбор либо запрещён, либо нужна авторизация.
- AI-анализ подключается только через webhook (n8n + локальная модель). Обязательным он не будет.
